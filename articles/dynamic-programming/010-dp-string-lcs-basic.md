## Concept

子序列（subsequence）是從字串挑出一些字元、保持原本先後順序但不必相鄰；子字串才要求相鄰。兩個字串的最長共同子序列（LCS）問的是：能同時從 a 與 b 挑出、在兩邊順序都一致的最長序列有多長。`"abcde"` 與 `"ace"` 的 LCS 是 `"ace"`，長度 3。

今天**兩個序列**各佔一個維度。狀態 `dp[i][j]`＝a 的前 i 個字元與 b 的前 j 個字元的 LCS 長度。索引慣例沿用昨天背包的「前 i 種」：表格索引 i 對應字串索引 i-1，表格開 (m+1) × (n+1)，多出來的第 0 列與第 0 欄代表空字串——空字串與任何前綴的共同子序列只有空序列，所以整列整欄都是 0。這是本課的邊界：和網格 DP 一樣先填好第一列與第一欄，只是那裡填 1（一條路），這裡填 0（零個字元）。

轉移看 a[i-1] 與 b[j-1]（兩個前綴各自的最後一個字元）是否相同，分兩條：

`dp[i][j] = dp[i-1][j-1] + 1`（相同）
`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`（不同）

相同那條說的是「一定直接配上，不必考慮不配」。它成立的前提有兩個：一、被比較的是兩個前綴各自的**尾端**，後面沒有字元；二、共同子序列的配對在兩邊索引都嚴格遞增（同一個索引最多配一次）。論證用交換：取任一最長的共同子序列 Z。若 Z 的最後一對就是 (a[i-1], b[j-1])，拿掉它，剩下的是前 i-1 與前 j-1 的共同子序列，長度不超過 `dp[i-1][j-1]`。若 Z 兩個都沒用到，把這一對接在 Z 後面仍合法（前提一：它們在最尾端，接上去不破壞順序），Z 就不是最長的，矛盾。若 Z 只用了其中一個，例如把 a[i-1] 配給某個 b[q]、q < j-1，改配給 b[j-1]：字元相同，而 Z 其他配對用到的 b 索引都小於 q（前提二），改完仍合法、長度不變，回到第一種情況。所以最長解一定可以改成以這一對收尾，`dp[i-1][j-1] + 1` 既達得到、也不會被超過。

不同那條：a[i-1] ≠ b[j-1]，Z 的最後一對不可能是它們倆，所以 Z 至少沒用到其中一個——沒用 a[i-1] 就是 `dp[i-1][j]` 的候選，沒用 b[j-1] 就是 `dp[i][j-1]` 的候選；兩個候選本身也都是合法的共同子序列。這兩堆會重疊（兩個都沒用到的 Z 同時屬於兩堆），但今天求的是 max：網格計數要不重不漏是因為加法會重複計數，max 只怕漏、不怕重。

## Thinking

填表順序照 Tabulation 的規則：(i, j) 依賴 (i-1, j-1)、(i-1, j)、(i, j-1)，列由上往下、列內由左往右即可。

滾動壓縮的依賴分析與網格 DP 相同：填第 i 列只讀第 i-1 列與本列，一條長度 n+1 的陣列就夠，不變式也一樣——開始填第 i 列第 j 格之前，`dp[0..j-1]` 已是本列新值、`dp[j..n]` 仍是上一列舊值。今天多一個需求：相同時要讀左上 `dp[i-1][j-1]`，而它在前一步被本列的 `dp[j-1]` 覆蓋了，所以覆寫 `dp[j]` 之前先把舊值存進 `diag`，它正是下一格的左上；每列開頭 `diag = 0`（第 0 欄）。j 反向走不行：`dp[j-1]` 還是舊值，讀到的是左上而不是左方，diag 也接不上。

為什麼是 `O(min(m, n))`：一條陣列的長度是欄數 + 1，列數不占空間，所以讓短的字串當欄、長的當列。能這樣對調是因為 LCS 對稱：共同子序列的定義不分哪個字串在前，所以 `LCS(a, b) = LCS(b, a)`；時間 O(m * n) 也對稱，對調不多花。

**貪婪為什麼不行、又什麼時候行。** 把「看到相同就配」拿去當貪婪（掃 a 的每個字元，配到 b 裡最早還沒用的相同字元）會錯：`"abab"` 對 `"ba"`，貪婪把 a 開頭的 `a` 配到 b 的第 2 個字元，之後 b 沒東西了，得 1；正解 `"ba"` 是 2。錯在它配的不是「尾端對尾端」——前提一破了，交換論證做不下去。但若題目改問「s 是不是 t 的子序列」（s 必須整個用掉），這個貪婪就對：s[i] 配到 t 裡最早的相同字元，任何晚配的方案都能換成早配而不影響後面，這是 O(|t|) 的雙指標；用 LCS 判也行——`LCS(s, t) == len(s)`——但此題不對稱，比的是 s 的長度。

**只能刪除時，最少步數為什麼是 `m + n - 2 * LCS`。** 兩邊刪到相同時留下的字串 R，是 a 的子序列也是 b 的子序列，即共同子序列；步數是 `(m - |R|) + (n - |R|)`。步數最少 ⇔ |R| 最大；任何共同子序列都能靠兩邊各自刪出來，所以 |R| = LCS 達得到，`m + n - 2 * LCS` 就是最少步數。

## Pattern Recognition

訊號：**兩個序列**、問「共同」「配對」「相似度」「把一邊變成另一邊要幾步」——狀態必須同時記兩邊的掃描進度，一維狀態記不住「a 掃到哪、b 掃到哪」兩件事。幾個變體只差在轉移：LCS 不同時取 max（可以跳過）；最長共同**子字串**不同時歸零（必須相鄰）；明天的 Edit Distance 把「跳過」升級成三種操作。看到「只能刪除」先想能不能化成 LCS；看到「一邊必須整個用掉」先試貪婪雙指標。

## Common Mistakes

每一條都由本篇 Tip 的程式碼施加單一改動實測：

- **表格索引與字串索引差 1**：把 TypeScript Tip 的 `c === b[j - 1]` 改成 `c === b[j]`，比較的字元整個右移一格，`"abcde"` 對 `"ace"` 從 3 變 2。表格第 i 列對應字串第 i-1 個字元，兩者不能混用。
- **相同時讀上方而不是左上**：把 `diag + 1` 改成 `up + 1`，`"aab"` 對 `"abb"` 從 2 變 3——b 的同一個 `a` 被上下兩列各配一次，違反「同一索引最多配一次」；改成 `dp[j - 1] + 1`（本列左方）同樣變 3，這次是 a 的同一個 `b` 配了兩次。
- **不同時只讀一邊**：把 `Math.max(up, dp[j - 1])` 改成 `up`，`"sea"` 對 `"eat"` 從 2 變 0；改成 `dp[j - 1]`，`"abcde"` 對 `"ace"` 從 3 變 1。跳過 a 的字元與跳過 b 的字元都是合法選擇，漏掉任一邊就把已配好的長度丟掉。
- **diag 沒更新或 j 反向**：把 `diag = up` 刪掉，diag 永遠是 0，每次相同都從 1 重數，`"abcde"` 對 `"ace"` 變 1；把 j 迴圈改成由右往左，`"abcde"` 對 `"ace"` 變 1，因為 `dp[j - 1]` 讀到上一列的舊值。

## Complexity

時間 O(m * n)：每格常數工作、只填一次。空間：完整表格 O(m * n)；滾動成一列後是欄數 + 1，讓短字串當欄即 O(min(m, n))。LCS 對稱，對調字串答案不變，所以這個選擇不影響正確性。

## Digest

兩個序列各佔一維：`dp[i][j]` 是 a 前 i 個與 b 前 j 個字元的 LCS 長度，表格 (m+1) × (n+1)，第 0 列與第 0 欄代表空字串、全為 0；表格索引 i 對應字串索引 i-1。轉移看兩個前綴的尾端字元：相同時 `dp[i][j] = dp[i-1][j-1] + 1`——在「比較的是兩個前綴的尾端、配對索引嚴格遞增」的前提下，任何最長共同子序列都能改成以這一對收尾，所以直接配上、不必考慮不配；不同時 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`，兩個候選會重疊，但 max 不怕重、只怕漏。滾動成一列時比網格多一個需求：左上值會被本列覆蓋，覆寫 `dp[j]` 前先把舊值存進 `diag`；j 必須由左往右。讓短字串當欄，陣列長度就是 min(m, n) + 1，可以對調是因為 LCS 對稱。「看到相同就配」拿去當貪婪會錯（`"abab"` 對 `"ba"` 得 1，正解 2），但「一邊必須整個用掉」的子序列判定，貪婪就對。只能刪除時，刪到相同的最少步數是 m + n - 2 * LCS：留下的一定是共同子序列，留越長刪越少，而任何共同子序列都能靠兩邊各自刪出來，所以最長的那個一定達得到。O(m * n) / O(min(m, n))。

## TypeScript Tip

單列滾動版；四組測資都含相同與不相同的字元，第二組走對調路徑且共同字元順序相反，第四組的重複字元擋住「配兩次」。

```typescript
function lcs(a: string, b: string): number {
  if (a.length < b.length) [a, b] = [b, a];   // 短的當欄
  const dp: number[] = new Array(b.length + 1).fill(0); // 第 0 列：全 0
  for (const c of a) {
    let diag = 0;                       // 第 0 欄，也是第 1 格的左上
    for (let j = 1; j <= b.length; j++) {
      const up = dp[j];                 // 尚未覆寫：上一列的值
      dp[j] = c === b[j - 1] ? diag + 1 : Math.max(up, dp[j - 1]);
      diag = up;                        // 舊 dp[j] 是下一格的左上
    }
  }
  return dp[b.length];
}
if (lcs("abcde", "ace") !== 3) throw new Error("ace");
if (lcs("ab", "bca") !== 1) throw new Error("order");
if (lcs("sea", "eat") !== 2) throw new Error("ea");
if (lcs("aab", "abb") !== 2) throw new Error("dup");
```

## Python Tip

雙列交替版：`prev` 是上一列、`cur` 是本列，左上直接讀 `prev[j - 1]`，不必暫存；順手寫出「只能刪除」的換算。

```python
def lcs(a: str, b: str) -> int:
    if len(a) < len(b):
        a, b = b, a                   # 短的當欄
    prev = [0] * (len(b) + 1)        # 第 0 列：空字串，全 0
    for ca in a:
        cur = [0] * (len(b) + 1)     # cur[0] = 0：第 0 欄
        for j, cb in enumerate(b, 1):
            cur[j] = prev[j - 1] + 1 if ca == cb else max(prev[j], cur[j - 1])
        prev = cur
    return prev[len(b)]

def min_delete(a: str, b: str) -> int:
    return len(a) + len(b) - 2 * lcs(a, b)   # 留下 LCS，其餘各自刪掉

assert lcs("ace", "abcde") == 3
assert lcs("abab", "ba") == 2      # 貪婪逐字配對只得 1
assert lcs("aab", "abb") == 2      # 同一個字元不能配兩次
assert min_delete("sea", "eat") == 2
assert min_delete("leetcode", "etco") == 4
```

## Takeaway

兩前綴尾端相同就接上（尾端對尾端、配對保序才成立）：dp[i][j] = 左上 + 1；不同取上、左最大；短字串當欄，空間 min(m, n)。
