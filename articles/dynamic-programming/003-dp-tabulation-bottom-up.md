## Concept

到今天為止，你已經用兩種方式解過 198 House Robber 與 70 Climbing Stairs：001 寫樸素遞迴，親眼看到呼叫樹裡同一個子問題被算了指數次；002 加上快取，讓每個子問題只真正算一次，時間降到 O(n)。今天還是同一題，**換掉的只有一件事：計算的方向**。記憶化是「從目標往下問、答案回頭填」；Tabulation 是「從最小的子問題開始，用迴圈一格一格往上填，填到目標為止」——沒有遞迴、沒有快取檢查，狀態就躺在一張陣列裡。

要做三個決定。**表格長什麼樣**：看昨天遞迴函式有幾個參數、各自的範圍。198 的函式只有一個參數「考慮到第幾間」，範圍 0 到 n，所以是一維、`n + 1` 格：`dp[i]` 定義為「只考慮前 i 間房（`nums[0..i-1]`）能搶到的最大金額」。**初始狀態填什麼**：把遞迴的 base case 直接翻譯——沒有房子搶 0 元，`dp[0] = 0`；只有一間就搶它，`dp[1] = nums[0]`（題目保證金額非負這一步才成立，若允許負數得寫 `max(0, nums[0])`）。**迴圈往哪走**：由依賴方向決定。轉移是 `dp[i] = max(dp[i-1], dp[i-2] + nums[i-1])`（第 i 間不搶就沿用前 i - 1 間的最佳；搶了就不能碰第 i - 1 間，只能接前 i - 2 間的最佳），右邊兩個索引都比 `i` 小，代表填第 `i` 格之前那兩格必須已經是正確值——所以 `i` 只能從 2 遞增到 n。反過來從 n 往 2 走（n ≥ 3 時兩種順序才真的不同），填 `dp[n]` 時讀到的 `dp[n-1]` 還是初始化的 0，整格就錯了。

「只能遞增」可以寫成迴圈不變式來確認：**填完第 i 格之後，`dp[0..i]` 全部正確**。i = 0：base case 填完，`dp[0] = 0` 對；i = 1：`dp[1] = nums[0]` 對。假設填完第 i - 1 格時成立，填第 i 格只讀 `dp[i-1]`、`dp[i-2]`，兩者都在已正確的範圍內，套上正確的轉移式，`dp[i]` 也正確。迴圈在 i = n 填完停下，`dp[n]` 就是答案。

跟 top-down 對照：兩者算的是同一組子問題、同樣 O(n) 時間，但表格版**沒有遞迴堆疊**——若 n 到十萬，top-down 的遞迴深度就是十萬層，Python 預設上限一千層直接 RecursionError，表格版只是一個迴圈；也沒有函式呼叫與快取查詢的常數開銷。代價是表格版一定把每一格都填滿，遇到「大部分狀態根本用不到」的問題，只算被問到的狀態的記憶化反而省。

## Thinking

拿 `nums = [2, 7, 9, 3, 1]` 走一遍。`dp[0] = 0`、`dp[1] = 2`；i = 2：`max(2, 0 + 7) = 7`；i = 3：`max(7, 2 + 9) = 11`；i = 4：`max(11, 7 + 3) = 11`；i = 5：`max(11, 11 + 1) = 12`。答案 `dp[5] = 12`，跟昨天記憶化版一致，只是每一格都是被迴圈「推」出來的，不是被遞迴「問」出來的。

寫的順序固定四步：一句話定義 `dp[i]` 的意義 → 從遞迴 base case 抄下初始狀態 → 看轉移式右邊的索引決定迴圈方向與起點 → 回傳目標格。索引位移最容易寫錯：`dp[i]` 是「前 i 間」，第 i 間房本身是 `nums[i-1]`，不是 `nums[i]`。

## Pattern Recognition

轉移式右邊的索引全都「已知且比左邊小」、狀態空間又幾乎每一格都會用到——這就是換成表格的時機。表格維度跟著遞迴參數走：一個參數一維，兩個參數（例如網格的列與欄）就是二維；初始狀態永遠是遞迴 base case 的翻譯。反之，若合法狀態只佔表格一小角、或依賴方向不是單純的遞增遞減，先留在記憶化。

## Common Mistakes

底下每一條都是把本篇 Python Tip 的 `rob` 改一行得到的。第一，**表格少開一格**：`dp = [0] * (n + 1)` 寫成 `[0] * n`，`rob([2, 7, 9, 3, 1])` 在 i = 5 寫 `dp[5]` 直接 IndexError（TypeScript 的陣列會默默長出來不報錯，但表格大小已跟定義對不上）。第二，**迴圈少跑最後一輪**：`range(2, n + 1)` 寫成 `range(2, n)`，`dp[5]` 永遠是初始的 0，回傳 0。第三，**方向反了**：`range(2, n + 1)` 寫成 `range(n, 1, -1)`，填 `dp[5]` 時 `dp[4]`、`dp[3]` 都還是 0，得到 `max(0, 0 + 1) = 1`。第四，**漏掉 `dp[1] = nums[0]`**：`dp[1]` 留 0，同一組輸入算出 10 而不是 12——錯在最前面的 base case，後面每一格跟著錯。第五，**索引位移**：`nums[i - 1]` 寫成 `nums[i]`，i = 5 時 `nums[5]` 越界。

## Complexity

時間 O(n)：迴圈 n - 1 輪，每輪一個 `max`。空間 O(n)：`n + 1` 格的表格。跟 top-down 同量級，但 top-down 的 O(n) 其實是兩份——快取一份、遞迴堆疊一份——表格版只剩一份，且沒有遞迴深度上限的問題。明天會把這唯一的一份也壓掉。

## Digest

198 第三次登場，換的是計算方向：不再從目標往下遞迴，改成從最小子問題起用迴圈往上填表。三個決定：表格維度跟著遞迴參數走（198 一個參數 → 一維 `n + 1` 格，`dp[i]` = 只考慮前 i 間的最大金額）；初始狀態是 base case 的翻譯（`dp[0] = 0`、`dp[1] = nums[0]`，金額非負才成立）；迴圈方向由依賴決定——轉移 `dp[i] = max(dp[i-1], dp[i-2] + nums[i-1])` 右邊索引都比 `i` 小，所以 `i` 只能從 2 遞增到 n，反向走會讀到還是 0 的格子（n ≥ 3 時兩種順序才真的不同）。不變式「填完第 i 格之後 `dp[0..i]` 全部正確」在 i = 0、1 由 base case 成立，之後每一格只讀已正確的兩格。對照 top-down：同樣 O(n) 時間，但沒有遞迴堆疊與呼叫開銷；代價是每一格都會填。常見錯：表格少一格、迴圈少一輪、方向反、漏 `dp[1]`、`nums[i]` 位移。

## TypeScript Tip

`new Array<number>(n + 1).fill(0)` 先把整張表歸零再填 base case；`noUncheckedIndexedAccess` 下讀表要加 `!`。測資能擋下方向反、少一輪、漏 `dp[1]`、`nums[i]` 位移與回傳錯格。

```typescript
import { strict as assert } from 'node:assert';

function rob(nums: number[]): number {
  const n = nums.length;
  if (n === 0) return 0;
  const dp: number[] = new Array<number>(n + 1).fill(0); // dp[i]：只考慮前 i 間
  dp[1] = nums[0]!;
  for (let i = 2; i <= n; i++) {                          // 依賴 i-1、i-2，只能遞增
    dp[i] = Math.max(dp[i - 1]!, dp[i - 2]! + nums[i - 1]!);
  }
  return dp[n]!;
}

assert.equal(rob([2, 7, 9, 3, 1]), 12);
assert.equal(rob([2, 1, 1, 2]), 4);
assert.equal(rob([1, 2, 3, 1]), 4);
assert.equal(rob([5]), 5);
assert.equal(rob([]), 0);
```

## Python Tip

`[0] * (n + 1)` 一行開表（等價於 `[0 for _ in range(n + 1)]`）。最後一條斷言是 5000 間房：遞迴版在預設 recursion limit 1000 下會 RecursionError，表格版只是一個迴圈。

```python
def rob(nums: list[int]) -> int:
    n = len(nums)
    if n == 0:
        return 0
    dp = [0] * (n + 1)          # dp[i]：只考慮前 i 間的最大金額
    dp[1] = nums[0]
    for i in range(2, n + 1):   # 依賴 i-1、i-2，只能遞增
        dp[i] = max(dp[i - 1], dp[i - 2] + nums[i - 1])
    return dp[n]

assert rob([2, 7, 9, 3, 1]) == 12
assert rob([2, 1, 1, 2]) == 4
assert rob([5]) == 5
assert rob([]) == 0
assert rob([1] * 5000) == 2500   # 隔一間搶一間
```

## Takeaway

維度看遞迴參數、初始值抄 base case、迴圈方向跟著依賴走：填完第 i 格時 `dp[0..i]` 必須已全部正確。
