## Concept

把昨天那張網格的 `+` 換成 `min`，就是今天的課。狀態定義照舊，只是意義改成「`dp[i][j]` 是從 (0, 0) 走到 (i, j) 的最小路徑和」；填表順序照舊，一維滾動的不變式照舊，依賴的兩格也照舊是上方與左方。真正要重寫的是正確性論證——計數與求極值靠的是兩件不同的事。

計數方程式 `dp[i][j] = dp[i-1][j] + dp[i][j-1]` 之所以對，是「到 (i, j) 的路徑被最後一步切成兩堆，不重不漏」。求極值不需要不重——同一條路徑被看兩次不影響 `min`——但多了一個新要求：最佳子結構。前提有兩條：每一步只能向右或向下；路徑的代價是沿途權重的加總。在這兩條前提下，`dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])` 成立的理由是交換論證：任取一條到 (i, j) 的最便宜路徑，去掉最後一格，剩下的是一條到 (i-1, j) 或 (i, j-1) 的路徑（第一條前提），而它必須是到那一格的最便宜路徑——否則換成更便宜的那條，接上同一個最後一格，總和更小（第二條前提：代價是加總，所以前段變便宜整條就變便宜），與「最便宜」矛盾。於是最佳解一定是「某個前置格的最佳解加自己」，對兩個前置格取 `min` 就抓到它。這裡沒有用到「權重非負」：方向受限就不會繞圈，負權重照樣成立，120 就允許負數。反過來，若目標改成「路徑上的最大值最小化」，第二條前提不成立，論證得重來。

邊界也跟著換：第一列只有一條路（一路向右），最小和就是累積總和 `dp[0][j] = dp[0][j-1] + grid[0][j]`，第一欄同理。昨天的「全是 1」是「只有一條路」在計數下的樣子，今天的累積總和是同一件事在求和下的樣子。

## Thinking

拿到題目先問三個問題。一、目標是加總還是別的？加總才能直接套上面的論證。二、每一格的前置格是誰？64 是上方與左方；120 的三角形第 i 列有 i + 1 格，(i, j) 的下一步是 (i+1, j) 或 (i+1, j+1)，這是不規則網格，「左方」這個詞已經不適用。三、從哪一端填？64 從左上往右下、答案在右下角。120 若從頂端往下填，第 i 列的 j = 0 只有父格 (i-1, 0)、j = i 只有 (i-1, i-1)，兩端都要特判；改成由底往上——`dp[i][j]` 改定義為「從 (i, j) 走到底的最小和」——每一格的兩個子格 (i+1, j) 與 (i+1, j+1) 一定都存在，`dp[i][j] = tri[i][j] + min(dp[i+1][j], dp[i+1][j+1])` 沒有例外，答案收在 `dp[0][0]`。

一維滾動要再做一次依賴分析，關鍵問題是「我要讀的是舊值還是新值」。64：新的 `dp[j]` 要讀上方舊值 `dp[j]` 與左方新值 `dp[j-1]`，所以 j 遞增，與昨天相同；第一欄則在進內圈之前先 `dp[0] += grid[i][0]`，讓 j = 1 讀到的左方是本列的值。120 由底往上：新的 `dp[j]` 要讀 `dp[j]` 與 `dp[j+1]` 兩個舊值，j 遞增時 `dp[j+1]` 還沒被覆寫，所以同樣遞增；若遞減，除了最右一格，`dp[j+1]` 都已是新值。兩題方向相同但理由不同，先答那個關鍵問題再決定方向。另一種寫法是把陣列填滿 `Infinity`、只把入口設 0，讓邊界併進同一個迴圈——`Infinity` 是 `min` 的單位元素，正如昨天的 0 是 `+` 的單位元素。

## Pattern Recognition

訊號：二維座標、移動方向受限不回頭、每一格帶成本、問路徑總和的極值。三者齊全就是今天的框架，`min` 換成 `max` 仍是同一課。要留意兩條分界。若移動可以四個方向，路徑會繞圈，依賴關係有環、填表順序不存在，得換 BFS 或 Dijkstra；若目標不是加總（例如路徑上最大值最小化），最佳子結構要重新論證。三角形、只能往下走一步的樓梯圖，都是把「前置格是誰」重新定義之後的同一個 Pattern。

## Common Mistakes

第一，第一列只抄權重不累積。把 TypeScript Tip 的 `dp[j] = dp[j - 1]! + grid[0]![j]!` 改成 `dp[j] = grid[0]![j]!`，`[[1,3,1],[1,5,1],[4,2,1]]` 從 7 變 3，第一列的每一格都被當成可以直接抵達。第二，第一欄忘記累加。刪掉 `dp[0] = dp[0]! + grid[i]![0]!` 那一行，同一組測資變 4，`dp[0]` 一直停在起點的權重。第三，累加放到內圈之後。把那一行搬到內圈後面，`[[1,9,9],[1,1,9],[9,1,1]]` 從 5 變 4，j = 1 讀到的「左方」其實是上一列的第一欄。第四，把 TypeScript Tip 的 `Math.min` 寫成 `Math.max`，兩組測資分別變 12 與 29。第五，三角形內圈少一格。把 Python Tip 的 `range(i + 1)` 改成 `range(i)`，`[[2],[3,4],[6,5,7],[4,1,8,3]]` 從 11 變 9，每列最後一格沒被更新、留著底列的舊值。第六，三角形 j 遞減。改成 `range(i, -1, -1)`，`dp[j+1]` 先被覆寫，答案變 12。

## Complexity

64：時間 O(m * n)，每格常數工作、只填一次；空間 O(n)，一維滾動陣列。120：n 列共 n(n+1)/2 格，時間 O(n^2)，空間 O(n)，即底列的長度。兩者若改用完整表格，空間各為 O(m * n) 與 O(n^2)。

## Digest

同一張網格，`+` 換成 `min`，`dp[i][j]` 改為到 (i, j) 的最小路徑和。在「只能向右或向下」與「代價是沿途權重加總」兩條前提下，`dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`：最便宜路徑去掉最後一格，剩下的必是某個前置格的最便宜路徑，否則換成更便宜的前段整條會更便宜，矛盾——這是最佳子結構，與計數要的不重不漏是兩件事；負權重不影響，目標改成非加總才要重論證。第一列與第一欄只有一條路，所以是累積總和 `dp[0][j] = dp[0][j-1] + grid[0][j]`，昨天的全 1 是同一件事在計數下的樣子。一維滾動：64 讀上方舊值與左方新值，j 遞增，且進內圈前先累加 `dp[0]`；三角形由底往上讀 `dp[j]`、`dp[j+1]` 兩個舊值，j 也遞增，理由不同。三角形由底往上填可避開頂端與兩側只有一個父格的特判。時間 O(m * n)，空間 O(n)。

## TypeScript Tip

第一列先做前綴和，之後每列先累加第一欄再進內圈。第一組測資的最佳路徑先向右兩步再向下兩步，光靠第一列的前綴和再直直往下就能重現，驗不到內圈的左方轉移；第二組是階梯形，最佳路徑右下交替，才會逼出它，兩組合起來上方與左方都被守住。

```typescript
function minPathSum(grid: number[][]): number {
  const m = grid.length, n = grid[0]!.length;
  const dp: number[] = new Array(n).fill(0);
  dp[0] = grid[0]![0]!;
  for (let j = 1; j < n; j++) dp[j] = dp[j - 1]! + grid[0]![j]!; // 第一列：累積總和
  for (let i = 1; i < m; i++) {
    dp[0] = dp[0]! + grid[i]![0]!; // 第一欄：只能從上方來，先累加再進內圈
    for (let j = 1; j < n; j++) dp[j] = grid[i]![j]! + Math.min(dp[j]!, dp[j - 1]!);
  }
  return dp[n - 1]!;
}
if (minPathSum([[1,3,1],[1,5,1],[4,2,1]]) !== 7) throw new Error("row then down");
if (minPathSum([[1,9,9],[1,1,9],[9,1,1]]) !== 5) throw new Error("staircase");
```

## Python Tip

三角形由底往上：複製底列當 `dp`，每一格讀兩個子格的舊值。測資的最佳路徑 2 → 3 → 5 → 1 在三層分別往左下、右下、左下，兩個子格都被選過；第一個斷言同時確認輸入沒被改動，第二個確認只有一列時迴圈不會執行。

```python
def minimum_total(tri: list[list[int]]) -> int:
    dp = tri[-1][:]  # 底列：每格的最小路徑和就是自己
    for i in range(len(tri) - 2, -1, -1):  # 由下往上
        for j in range(i + 1):  # 第 i 列有 i + 1 格；j 遞增時 dp[j + 1] 還是舊值
            dp[j] = tri[i][j] + min(dp[j], dp[j + 1])
    return dp[0]

t = [[2], [3, 4], [6, 5, 7], [4, 1, 8, 3]]
assert minimum_total(t) == 11 and t[-1] == [4, 1, 8, 3]  # 輸入不被改動
assert minimum_total([[-10]]) == -10
```

## Takeaway

方向受限且代價是加總時，最便宜路徑的前段必是前置格的最便宜路徑：dp = 自己 + min(上方, 左方)，邊界是累積總和。
