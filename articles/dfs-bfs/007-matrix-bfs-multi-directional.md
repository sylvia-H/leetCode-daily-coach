## Concept

這是你第三次遇到腐爛的橘子。queue 模組的 Matrix Multi-Source BFS 那一課用「虛擬超級源點」說明了為什麼把所有源點一次放進佇列等價於單源 BFS，並用距離矩陣兼任 visited；graph 模組的 Graph BFS Traversal 那一課把它放回一般圖，證明了佇列任何時刻只含距離 d 與 d+1 的節點、且入隊當下就要標記。今天不重講那兩件事，而是把 BFS 接上昨天的網格模板——同一個方向陣列 (1, 0)、(-1, 0)、(0, 1)、(0, -1)，同一個「先邊界、再內容」的檢查，同一種就地標記——並釘死三個前兩課帶過但沒有寫成一句話的環節：起始佇列怎麼建、「分鐘數等於層數」這條不變式的精確陳述、以及迴圈結束後殘留的新鮮格子代表什麼。

先把「同時擴散」說成一句可以驗證的話：在每一步成本相同的前提下，一顆新鮮橘子腐爛的分鐘數，等於它到「最近的」初始腐爛橘子、只經過橘子格子的最短步數。多源 BFS 算的正是這個最小值：所有源點放在第 0 層，就是超級源點走完第一步的狀態，之後單源 BFS「首次觸及即最短」的性質原封不動。分鐘數等於層數的不變式因此可以寫成：在鄰居於入隊當下就被標記的前提下，第 k 層剛入隊完畢、還沒開始展開時，恰好是「最短步數 ≤ k」的那些新鮮橘子已被標記入隊，最短步數 > k 的一顆都沒動。k = 0 時佇列裡只有源點，成立；處理第 k 層時，每顆最短步數 = k + 1 的橘子必定緊鄰某顆最短步數 = k 的橘子，會在這一層被標記入隊，而最短步數更大的橘子沒有這樣的鄰居，不會被動到，不變式往前推一層。答案就是最後一個真的有橘子被標記的層數；到不了的橘子永遠不會入隊，迴圈結束後仍是 1，題目要求回報 -1。

昨天的 DFS 為什麼不能做這件事？DFS 走完同一塊區域，順序卻與距離無關。`[[2, 1, 1], [1, 1, 0]]` 從 (0, 0) 出發、先往下走，會依 (1, 0)、(1, 1)、(0, 1)、(0, 2) 的順序到達，(0, 1) 在遞迴深度 3 才被碰到，但它離源點只有 1 步。層級是 BFS 才有的性質。

## Thinking

拿到題目後分四步。第一步，掃一遍網格：值為 2 的座標全部推進佇列，這就是第 0 層；同時數出新鮮橘子的個數 fresh，它會兼任「還有沒有事情要做」與「有沒有殘留」兩個判斷。第二步，主迴圈以「層」為單位：把佇列裡現有的座標一次全部取出當成這一層（TypeScript 用 `q.splice(0)`，Python 用 `for _ in range(len(q))` 配 `popleft()`），處理途中新入隊的座標自然構成下一層；每個座標套昨天的四方向與邊界檢查，只對值為 1 的鄰居動手——改成 2、fresh 減一、入隊，三件事在同一處完成，這就是「入隊即標記」。第三步，一層取完後分鐘數 mins 加一。迴圈條件寫成「佇列非空且 fresh > 0」而不是只看佇列：最後一層把最後一顆橘子標記後 fresh 歸零、迴圈立刻停，不會為了「取出最後一層卻沒有新格子」多算一輪；一開始就沒有新鮮橘子時迴圈一次都不跑，答案 0。第四步，收尾：fresh 仍大於 0 就回 -1，否則回 mins。若題目要的是每一格各自的時間而不是整體的最大值，就換回 queue 模組的距離矩陣寫法，把「層」改成逐格記錄的 dist。

## Pattern Recognition

三個訊號指向多源網格 BFS。一、情境是同步蔓延：腐爛、傳染、水流、火勢，多個起點在同一時刻開始，問「全部完成要多久」或「每一格離最近的起點多遠」。二、每走一格的成本相同——成本不等就得換 Dijkstra。三、輸入仍是網格，鄰居仍由方向陣列算出，昨天的邊界檢查與就地標記照用。與昨天的分工線在「問什麼」：問一塊區域的成員或總量，DFS 與 BFS 都行；問時間或距離，只有 BFS 能用層數回答。另外注意起點的數量與答案無關：起始佇列放一個座標就是單源，放一批就是多源，主迴圈一個字都不用改。

## Common Mistakes

第一，多算一輪。把下方 TypeScript Tip 的迴圈條件 `q.length && fresh > 0` 改成 `q.length`：`[[2, 1]]` 在第 1 層標記了唯一的新鮮橘子，但佇列裡還有那顆剛入隊的橘子，迴圈再跑一層、什麼都沒發生、mins 仍加一，回 2，正解是 1；Tip 的測資一會從 2 變成 3。第二，忘記標記。刪掉 Tip 裡 `g[nr]![nc] = 2;` 那一段：`[[2, 1, 2]]` 中間那顆橘子會被左右兩個源點各推一次、fresh 減兩次變成 -1，最後被判成「有殘留」回 -1，正解是 1。第三，忘記殘留檢查。把最後一行 `return fresh === 0 ? mins : -1;` 改成 `return mins;`：`[[2, 0, 1]]` 右邊那顆橘子被水隔開、永遠不會入隊，卻回 1，正解是 -1。第四，與昨天相同的邊界問題在 BFS 裡一樣會發生：把 Python Tip 的 `0 <= nr < R` 改成 `nr < R`，Python 測資二 `[[2, 0, 1], [0, 0, 1], [1, 1, 1]]` 的 (0, 0) 往上會經由 `g[-1]` 回繞到 (2, 0)，被水包住的五顆橘子全被標記，回 4，正解是 -1。

## Complexity

時間 O(R * C)：起始掃描一遍；之後每一格最多入隊一次（入隊即標記），每次出隊檢查四個鄰居，總工作量與格數成正比；源點有幾個都不影響這個上界，它們只是「入隊一次」的格子。空間 O(R * C)：就地把 1 改成 2 不需額外 visited；佇列最壞同時容納與格數同階的座標（例如全部都是初始腐爛的橘子）；`splice(0)` 每層搬移一次當層的座標，總搬移量等於總入隊次數，時間仍是 O(R * C)。

## Digest

多源網格 BFS：把所有初始源點放進起始佇列當第 0 層，之後跑與單源完全相同的逐層迴圈。前提是每走一格的成本相同、且鄰居在入隊當下就標記；在這兩個前提下，第 k 層剛入隊完畢時，恰好是最短步數 ≤ k 的格子已被標記，因此格子被觸及的層數就是它到最近源點的最短步數，整體完成時間是最後一個真的有新格子被標記的層數。實作沿用昨天的方向陣列、先邊界再內容的檢查與就地標記（1 改成 2）；起點在第 0 層，迴圈條件加上「還有新鮮格子」避免多算一輪；迴圈結束後仍未被標記的目標格代表任何源點都到不了，依題意回 -1。DFS 的走訪順序與距離無關，不能用來算層數。時間與空間皆為 O(R * C)。

## TypeScript Tip

`q.splice(0)` 一次取出整層，新入隊的就是下一層；fresh 兼任終止與殘留判斷。

```typescript
const DIRS = [[1,0],[-1,0],[0,1],[0,-1]] as const;
function rot(g: number[][]): number {
  const R = g.length, C = g[0]!.length, q: [number, number][] = [];
  let fresh = 0, mins = 0;
  g.forEach((row, r) => row.forEach((v, c) => v === 2 ? q.push([r, c]) : v === 1 && fresh++));
  while (q.length && fresh > 0) {
    for (const [r, c] of q.splice(0)) {
      for (const [dr, dc] of DIRS) {
        const nr = r + dr, nc = c + dc;
        if (nr < 0 || nr >= R || nc < 0 || nc >= C || g[nr]![nc] !== 1) continue;
        g[nr]![nc] = 2; fresh--; q.push([nr, nc]);
      }
    }
    mins++;
  }
  return fresh === 0 ? mins : -1;
}
if (rot([[1,1,0,1],[2,1,0,2],[1,0,1,2]]) !== 2 || rot([[2,0,1]]) !== -1) throw Error("bad");
```

## Python Tip

`popleft()` 是 O(1)，`range(len(q))` 只取這一層；下界 `0 <= nr` 不能省，負索引會回繞。

```python
from collections import deque
DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))
def rot(g: list[list[int]]) -> int:
    R, C = len(g), len(g[0])
    q = deque((r, c) for r in range(R) for c in range(C) if g[r][c] == 2)
    fresh, mins = sum(row.count(1) for row in g), 0
    while q and fresh > 0:
        for _ in range(len(q)):
            r, c = q.popleft()
            for dr, dc in DIRS:
                nr, nc = r + dr, c + dc
                if 0 <= nr < R and 0 <= nc < C and g[nr][nc] == 1:
                    g[nr][nc] = 2; fresh -= 1; q.append((nr, nc))
        mins += 1
    return mins if fresh == 0 else -1

assert rot([[1,1,0,1],[2,1,0,2],[1,0,1,2]]) == 2
assert rot([[2,0,1],[0,0,1],[1,1,1]]) == -1
```

## Takeaway

所有源點放進起始佇列當第 0 層、入隊即標記、逐層推進；成本均等時層數就是到最近源點的分鐘數，殘留格回 -1。
